# はじめかた（鳥人間チーム向け）

ターミナルを使ったことがない人が、**Claude Desktop で話しかけるだけで機体を解析する**ところまでの手順です。

- 対象: macOS のみ（Linux と Windows は未検証です）
- 所要時間: 準備 15 分、最初の解析 1 分
- 前提知識: 空力の基礎。プログラミングは不要です

---

## 1. これは何か

flow5 は渦格子法（VLM）の解析ソフトです。flow5ctl は、その flow5 を **AI から操作できるようにする道具**です。

| できること | できないこと |
|---|---|
| 翼・尾翼の三次元解析（CL、抗力、モーメント） | 桁の設計、構造解析、たわみ |
| 静安定余裕・中立点・トリム | フラップ、エルロン、動翼（flow5 の仕様上ムリ） |
| 地面効果の有無を1回で比較 | ワイヤ・フェアリング・パイロットの抗力 |
| 翼根曲げモーメント（空力荷重のみ） | 最適化（意図的に対象外） |
| 翼型の2次元極曲線の自動計算 | 胴体まわりの流れ |

**いちばん大事な前提**: この道具が出す L/D は**揚力面だけ**の値です。実機の値ではありません。詳しくは [6. 警告の読み方](#6-警告の読み方) を見てください。

## 2. 用意するもの

| # | もの | 入手先 | 備考 |

| 1 | flow5 本体 | [flow5.tech](https://flow5.tech) | flow5ctl には同梱されていません |

uv のインストールだけは**一度だけターミナル**を使います。ターミナル.app を開いて、次の1行を貼って Enter を押してください。

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

これ以降ターミナルは使いません。

## 3. Claude Desktop につなぐ

設定ファイルを1つ作ります。場所は次のとおりです。

```
~/Library/Application Support/Claude/claude_desktop_config.json
```

中身をこれにします。

```json
{
  "mcpServers": {
    "flow5": {
      "command": "uvx",
      "args": ["--from", "flow5ctl[plot]", "flow5ctl", "mcp"]
    }
  }
}
```

Claude Desktop を再起動して、こう聞いてください。

> flow5 の状態を確認して

flow5 のバージョンが返ってくれば成功です。返ってこないときは [8. うまくいかないとき](#8-うまくいかないとき) へ。

## 4. 最初の1機

そのまま日本語で話しかければ動きます。たとえば、こう。

> 翼幅 30 m、翼根コード 1.1 m、テーパ 0.45 の人力機を作って解析して。
> パイロットは 65 kg、機体重量は 35 kg。巡航 7.5 m/s で、地面効果ありとなしを比べて。

Claude が裏側でやっていることは次のとおりです。

1. `design.yaml` という設計ファイルを作る
2. 翼型の2次元極曲線を必要な Re の範囲で自動計算する（初回だけ 30〜60 秒かかります）
3. flow5 を走らせる
4. 結果を要約し、**おかしいところに警告を付ける**

グラフが欲しいときは「極曲線のグラフを見せて」と言えば PNG が返ります。

## 5. 返ってきた数字の読み方

| 数字 | 意味 | 見るべきところ |
|---|---|---|
| `CL_alpha` | 迎角1度あたりのCLの増え方 | アスペクト比なりの値か |
| `best L/D` | 最良揚抗比 | **揚力面だけの値**。実機はこれより悪い |
| `static margin` | 静安定余裕（%MAC） | **正であること**。人力機なら 5〜15 % |
| `pitch stiffness` | 重心高さの効果を含めた縦の復元力 | 教科書の帯と比べてはいけない別物 |
| `trim alpha` | 水平飛行が釣り合う迎角 | 失速に近すぎないか |
| `root bending` | 翼根の曲げモーメント（N·m） | 空力荷重のみ。桁の設計値ではない |
| `load factor` | その点の揚力 ÷ 機体重量 | **1 に近いか**。遠いと荷重が過大 |

### 静安定余裕と「ピッチ剛性」は別物です

人力機はパイロットが重心の大半で、しかも**翼よりずっと下**にいます。重心が下にあると、機体が傾いたときに力の向きが変わる分だけ余分な復元力が出ます。

- **静安定余裕** … 教科書・尾翼容積の式・公表重心が指しているのはこちら
- **ピッチ剛性** … 重心高さの効果を含めた、実際の粘り

この2つを取り違えると、**不安定な機体を安定だと読み違えます**。開発中、同梱の人力機の例が実際にこの状態でした（静安定余裕 −10.1 % ＝ 不安定、ピッチ剛性 +3.4 %、しかも L/D は 50.6 と出ていました）。例は修正済みで、今は flow5ctl が両方を別々に出し、静安定余裕がマイナスなら「飛べない」とはっきり言います。

## 6. 警告の読み方

⚠ が付いた文は「読み飛ばしてはいけない」ものです。

| 警告 | 意味 | どうするか |
|---|---|---|
| 静安定余裕がマイナス | **重心が中立点より後ろ。ピッチが発散する** | 重心を前に。「静安定余裕 10 % になる重心を求めて」と頼む |
| 静安定余裕が帯の外 | 安定だが余裕が設計値と違う | 重心か尾翼容積を見直す |
| この運転点は自重の N 倍 | 固定速度の極曲線なので釣り合っていない | 桁の荷重に使うなら、先にトリムするか T2 極曲線で |
| 揚抗比は揚力面のみ | ワイヤ・フェアリング・パイロットが入っていない | 提示される「現実的な帯」と比べる |
| XFoil が収束しなかった | 2次元極曲線に穴があり、抗力が内挿されている | 迎角刻みか ncrit を変えて再計算 |
| 地面効果が入っている | 地面効果ありの値を出している | 地面効果なしの値も必ず併記する |

### 抗力について、いちばん誤解しやすいこと

flow5 が計算するのは**翼と尾翼の抗力だけ**です。人力機の場合、実際にはこれ以外に次のものがあります。

- 張り線（フライングワイヤ）
- フェアリングとパイロットの体
- 接合部の干渉抗力
- 表面の仕上げ

**これらを足すと、モデルの抗力の 20〜40 % 増しになります。** flow5ctl はこの帯を必ず併記するので、公表値と比べるときは**帯のほうと比べてください**。素の値と比べると「20 % も合わない」と誤読します。

### 翼型の「改」は無視できません

再現した3機のうち、翼型の改修内容が公表されている1機（WASA 2013、FX76MP160 と FX76MP120 の混合で翼厚 14.9 %）だけが、抗力の帯にきれいに収まりました。原型の翼型で代用した2機は大きく外れました。

**チーム独自の翼型改修は L/D に 40 % 前後効きます。** 原型で代用した結果は、参考値としても弱いと考えてください。

## 7. やってはいけないこと

- **この結果だけで有人機を作らないでください。** 渦格子法は失速も、たわみも、フラッタも扱いません
- **絶対値を信じすぎないでください。** 比較（A案とB案のどちらが良いか）には強く、絶対値には弱い道具です
- **警告を消さないでください。** 警告は「計算が失敗した」ではなく「その数字の意味はこうだ」と言っています

---

## 8. うまくいかないとき

| 症状 | 原因 | 対処 |
|---|---|---|
| flow5 が見つからない | 標準以外の場所にある | 設定に `"env": {"FLOW5CTL_FLOW5": "/パス/flow5"}` を足す |
| `uvx` が見つからない | uv が PATH にない | ターミナルで `which uvx`。出なければ uv を入れ直す |
| 開発版を試したい | 公開版ではなく手元のコードを使いたい | `"--from"` をチェックアウト先のパスにする（[MCP.md](../MCP.md) 参照） |
| 解析が返ってこない | 2次元極曲線の初回計算 | 初回だけ 30〜60 秒かかります |
